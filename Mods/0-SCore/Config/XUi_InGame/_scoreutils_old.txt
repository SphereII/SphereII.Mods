        <!--
            =====================================================================
            SCORE UTILITIES
            =====================================================================

            The player-facing settings screen, reached from the ESC menu button in
            ingameMenuSCore above. Every row is a cvar-backed checkbox; Save writes them
            all to the player and closes the window.

            [ HOW IT IS WIRED ]
            XUiC_SCoreUtilities does not know any of these rows by name. On open it walks
            GetChildrenByType<XUiC_ToggleButtonCVar>() and seeds each one, and Save walks
            the same set writing Buffs.SetCustomVar(CVarName, 0/1). So adding a setting
            here is a one-line change with no C# to match - the only name the controller
            looks up is SCorebtnSubmit.

            Two shapes of cvar go through that loop:
              - a plain player cvar, e.g. quietNPC or $WeaponSway, read by whichever
                feature owns it
              - a Class_Feature pair, e.g. AdvancedPrefabFeatures_DisableFlickeringLights.
                OnOpen splits these on the first underscore and seeds the initial state
                from Configuration.CheckFeatureStatus(class, feature) when the player has
                no cvar of that name yet.

            [ GRID LAYOUT ]
            The grid is one column and every child is one cell, so the bare <rect/> entries
            are deliberate blank spacers before each section heading, not leftovers. Keep a
            spacer and a heading together when adding a section, and remember the count is
            what positions everything below it.

            [ TOGGLE GEOMETRY ]
            Size, depth and font live on the togglebuttonCVar template defaults, since this
            window is its only consumer. Rows carry just what makes them different: name,
            cvar and captions. The template comment records the attributes that used to be
            repeated here and never had any effect.
        -->

                        that recurses first-match-wins, so a controller looking for its own border
                        can bind to a stray one several levels down. See the traps list in
                        Mods/Ideas/XUI_SYSTEM_REFERENCE.md.

                        through the lower toggles, so it is sized to the content instead.

                        Which means it depends on the Locks block above: with it the grid is
                        nineteen cells, without it fifteen, a difference of four cells or 136px.
                        Hence the two variants - same top edge, shorter box when the lock picking
                        section is absent. Adjust both together when adding or removing a row, and
                        note the frame is only as good as that arithmetic; it has not been seen
                        rendered.
